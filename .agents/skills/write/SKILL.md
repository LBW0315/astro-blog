# BUNBOUの記事作成

ユーザーが `$write` と一緒に渡したテーマ、メモ、下書き、またはファイルパスを入力として扱う。

## 進め方

1. 入力内容を確認する。
   - ファイルパスの場合は、そのファイルを読み込んで材料にする。
   - テーマだけの場合は、記事に必要なことを1問ずつ、5〜8問を目安に質問する。
   - メモがある場合は、不足している情報だけを質問する。
   - 選択肢で答えやすい質問は、短い選択肢を提示する。
2. タイトル案、ジャンル、構成案を提示し、ユーザーの了承を得てから執筆する。
3. `src/content/blog/` に既存記事と同じ形式のMDX記事を作成し、必要な図解や部品を追加する。
4. 公開前チェックとビルドを行い、実際の記事ページを確認できる状態にする。
5. 変更内容と確認結果を簡潔に報告し、追加修正を待つ。デプロイは実行しない。

## 文章

- ユーザー自身の文章の雰囲気や言い回しをできるだけ残し、誤字や読みにくい箇所だけを整える。
- 見出し、箇条書き、コードブロックなどを使い、Markdownとして読みやすく構成する。
- 注意や補足として見せるべき箇所には、既存の `Callout` コンポーネントを使う。
- 既存記事を確認し、語り口、frontmatter、内部リンク、コンポーネントの使い方を揃える。

## イラスト・図解

理解を助ける図解は積極的に使う。手順の流れ、仕組みの関係図、比較、before / afterなどが対象になる。

- 既存の図解コンポーネントで合うものがあれば再利用する。
- 記事専用の図解はSVGで作成してよい。
- 他の記事でも使い回せる新しい図解部品を追加する場合は、実装前に案を提示する。
- 新しいパッケージが必要な場合は、追加前にユーザーへ相談する。
- 画像には内容に合った `alt` を付け、SVG図解には `aria-label` または `aria-labelledby` で内容が分かるアクセシブルな名前を付ける。

### タッチ

BUNBOUらしい、ノートにペンで描いたような手描き風・アナログ感で統一する。ただし、読みやすさを最優先する。

- 線と図形には、SVGの `feTurbulence` と `feDisplacementMap` を使った控えめなゆらぎを付けてよい。目安は `scale` 3程度とする。
- SVGフィルターのIDは、同じページ内の他の図と重ならない名前にする。
- アイコンは、公式サービスアイコンを使わず、少ない線で描いたシンプルな線画にする。
- 文字にはゆらぎをかけず、手書き風フォントも使わない。サイトの見出し・本文フォントを使う。
- 比較表や料金表は画像化せず、読み上げとコピーが可能なMarkdownの表にする。
- 飾りだけの図は増やさない。要素を絞り、ラベルを対象の近くに置き、矢印で読む順番を明確にする。
- 線と色の意味を記事間で統一する。
  - 青磁の実線：できている、完成している部分。
  - 灰桜の点線と「これから」のラベル：これから作る、予定している部分。
- 375px程度の画面で文字が小さくなりすぎないようにする。図の中の文字は14px以上を目安にする。
- 実装前に `src/components/diagrams/AwsBlogArchitecture.astro` と `src/components/diagrams/DeployFlow.astro` を参考にする。

## 色

- 強調、分類、図解の色分けには色を使ってよいが、サイトのデザイントークンから選び、記事や部品に色コードを直接書かない。
- 必要な色がない場合は、デザイントークンへの追加を実装前に提案する。
- 文字と背景のコントラスト比はWCAG AAを満たし、ライトモードとダークモードの両方で読めるようにする。
- 色だけで意味を伝えず、アイコン、ラベル、線種などを併用する。
- 1つの図や段落で使う色は3色程度までに抑える。

## 公開前チェック

次を確認する。問題があれば、ユーザー固有の言い回しを明らかな誤りでない限り維持したうえで、修正案とともに報告する。

- 誤字脱字と表記ゆれ。例：同じ記事内での「スマホ」と「スマートフォン」の混在。
- 画像や図解の代替テキストまたはアクセシブルな名前。
- リンク切れとコードブロックの言語指定。
- タイトル、`description`、ジャンル、公開日。
- 家族の名前や住所が分かる写真などの個人情報。

## 確認

- `npm run build` を実行する。
- 記事ページをブラウザで表示し、デスクトップ幅と375px程度のスマホ幅、ライトモードとダークモードで確認する。
- 開発サーバーを起動する場合は、リポジトリの `AGENTS.md` に従って `astro dev --background` を使い、確認後に停止する。
- どこをどう整えたか、どの図解や色を使ったか、公開前チェックとビルドの結果を簡潔に伝える。
- デプロイは実行しない。
